# Документация для разработчиков

Набор про то, **как устроена платформа изнутри** и **почему она устроена
именно так**. Рассчитан на разработчика, который знает Django и React, но эту
кодовую базу видит впервые.

## Как устроено доменное руководство

Все одиннадцать написаны по одной рубрике. Раздел, пустой для конкретного
домена, сохраняется с пометкой «нет» — отсутствие тоже факт.

1. Назначение и границы — в том числе чего домен намеренно **не** делает
2. Модели — схема связей и назначение каждой
3. Публичный контракт `interface.py` — единственная легальная дверь снаружи
4. Ключевые сценарии — разбор `services/` по коду
5. HTTP-эндпоинты — ссылка на `API.md` плюс то, чего там нет
6. Фоновые задачи Celery
7. Права и гейты
8. **Инварианты и подводные камни** — что сломается и почему
9. Тесты

Раздел 8 обычно самый полезный: в нём то, что не выводится из чтения кода.

## Соглашения этого набора

- Ссылки на код — от корня репозитория, с номером строки:
  `backend/apps/hr/services/calendar_service.py:42`. Номера могут разъехаться при
  рефакторинге; имена функций и файлов надёжнее.
- Утверждение о поведении означает, что оно сверено с кодом при написании.
  Неподтверждённое помечается явно.
- Схемы — mermaid прямо в тексте: GitHub их рисует, они версионируются и не
  устаревают молча.
