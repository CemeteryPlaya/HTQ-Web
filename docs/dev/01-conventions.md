# Сквозные соглашения

Правила, общие для всех одиннадцати доменов. Нарушение любого из них ломает не
только свою аппку, поэтому раздел стоит прочитать до первой правки кода.

Смежные документы: [00-overview.md](00-overview.md) — из чего состоит
платформа; [API.md](../../API.md) — таблица маршрутов;
[backend/README.md](../../backend/README.md) — как завести новый домен.

---

## 1. Три слоя: views → services → models

Вью — тонкий диспетчер: разобрать запрос, вызвать сервис, оформить ответ.
Бизнес-логики в нём нет. Вся логика живёт в `backend/apps/<домен>/services/`.

Практическое следствие: **чтобы понять поведение, читайте `services/`, а не
`views.py`.** Ищущий логику во вью найдёт разбор query-параметров и решит, что
её нет.

Объёмы неравномерны — от 5647 строк сервисов в `tasks` до нуля в `core`
(`core` — не домен, а общий фундамент).

---

## 2. HTTP-слой: `api_view`, а не DRF

DRF стоит в зависимостях, но HTTP-слой платформы **не на нём**. Всё идёт через
самописный декоратор `htqweb.http.api_view` (`backend/htqweb/http.py:74`).

> Если в старой документации встретите DRF ViewSets и `backend/tasks/viewsets/` —
> это описание раскладки, которой в репозитории нет. Например
> `docs/architecture.md:18`, хотя тот же файл сверху несёт предупреждение об
> устаревании.

### Параметры

```python
api_view(methods=("GET",), auth="jwt", body=None, status=200, admin=False)
```

| Параметр | Смысл |
|---|---|
| `methods` | Кортеж разрешённых методов. Всё остальное — 405 `{"detail": "Method Not Allowed"}` |
| `auth` | `"jwt"` — Bearer-токен обязателен; `None` — публичная ручка |
| `body` | Класс Pydantic. Тело разбирается и валидируется до вызова функции и приезжает в `kwargs["data"]` |
| `status` | Код успешного ответа (например 201 на создание) |
| `admin` | Требовать администратора платформы поверх `auth="jwt"` |

`admin=True` вместе с `auth=None` — не тихая ошибка, а `ValueError` **в момент
декорирования** (`backend/htqweb/http.py:81`): проверка администратора смотрит
в `request.token`, который при `auth=None` всегда `None`. Падение при импорте
лучше, чем загадочный 403 в проде.

### Что декоратор делает с возвращаемым значением

`backend/htqweb/http.py:110-118` — порядок проверок важен:

1. Pydantic-модель → `JsonResponse` с `model_dump(mode="json")`
2. Непустой список Pydantic-моделей → JSON-массив
3. `dict` или `list` → как есть, `safe=False`
4. Всё прочее (готовый `HttpResponse`: файлы, редиректы) → возвращается без
   изменений, **`status` при этом игнорируется**

### Конверт ошибок

Любая ошибка — всегда `{"detail": ...}`. Это контракт, унаследованный от
FastAPI-поколения, и фронт на него завязан.

| Код | Когда |
|---|---|
| 400 | `SuspiciousOperation` |
| 401 | Нет заголовка `Bearer`, токен не разобрался или это не access-токен |
| 403 | `admin=True` не прошёл, либо `PermissionDenied` из сервиса |
| 404 | `Http404` — текст исключения попадает в `detail` |
| 405 | Метод вне `methods` |
| 422 | Тело не прошло валидацию Pydantic; `detail` — список `{type, loc, msg}` |
| 500 | Любое необработанное исключение, с записью в лог `htqweb` |
| 503 | Сервис отключён — см. раздел 5 |

**Про 422 есть отдельная история, которую стоит знать.** Функция
`validation_detail` (`backend/htqweb/http.py:27`) намеренно использует
`exc.errors()`, а не `exc.json()`. Pydantic держит в записи об ошибке поле
`input` — срез исходных байтов тела. На любом не-ASCII символе срез рвётся
посередине UTF-8-последовательности, `exc.json()` на таком падает, причём
падает внутри обработчика ошибки — внешний `except` его не ловит. Итог: любая
форма с русским текстом и хоть одним невалидным полем отвечала голым 500 вместо
422. Поле `input` из ответа выброшено намеренно: клиент и так знает, что
отправил, а эхо тела запроса — лишний способ утащить в лог лишнее.

### Class-based вариант

`htqweb.http.ApiView` (`backend/htqweb/http.py:139`) — альтернатива для аппок,
предпочитающих CBV; первой такой стала `apps.contracts`. Функциональный стиль
остаётся основным: так написаны все домены, пришедшие из FastAPI-поколения.

Важно: `api_view` навешивается **пометодно** через `method_decorator`, потому
что режим авторизации у разных методов одного URL разный (GET — `auth="jwt"`,
POST — `admin=True`), а один `api_view` связывает ровно один режим с одной
функцией. `OPTIONS` из `http_method_names` убран намеренно — иначе Django
обслужил бы его сам, в обход авторизации.

## 3. URL монтируются сами

`backend/htqweb/urls.py` перебирает установленные аппки и монтирует каждую, у
которой в `AppConfig` объявлен `API_PREFIX` и есть модуль `urls`:

```python
for _config in django_apps.get_app_configs():
    _api_prefix = getattr(_config, "API_PREFIX", None)
    if _api_prefix and module_has_submodule(_config.module, "urls"):
        urlpatterns.append(path(_api_prefix, include(f"{_config.name}.urls")))
```

**Заведение нового домена не требует правки `backend/htqweb/urls.py`** — достаточно
`API_PREFIX` в `apps.py`. Так сделано, чтобы этот файл не был точкой конфликта
при параллельной работе.

`apps.core` в цикл не попадает: у него нет `API_PREFIX`, свой префикс
`api/core/v1/` он объявляет внутри `backend/apps/core/urls.py`, а сам смонтирован в
корень выше.

### `APPEND_SLASH = False`

Django не досылает редирект на слэш. Поэтому `urls.py` доменов регистрируют
**обе** формы пути — со слэшем и без — везде, где фронт может прислать любую.
Забыть парную регистрацию — получить 404 на ровном месте.

## 4. Домены изолированы: только через `interface.py`

Соседний домен доступен **исключительно** через его модуль
`apps.<домен>.interface`. Запрещено:

- импортировать `apps.<чужой>.models` или `apps.<чужой>.services`;
- заводить внешние ключи между доменами.

Правило не на честном слове — его стережёт тест
`backend/apps/core/tests/test_app_isolation.py`. Он же переживёт вас: попытка
срезать угол упадёт в CI.

Чтобы увидеть, кто чем пользуется у домена:

```bash
grep -rn "apps\.<домен>\.interface" backend/apps --include=*.py
```

Инвариант пережил обе миграции архитектуры без изменений — именно он позволил
сначала растащить монолит на девять сервисов, а потом собрать обратно.

## 5. Домены отключаются на ходу

Любой домен выключается рубильником, и это видно на четырёх границах разом.

Источник истины — строка `ServiceStatus` в БД (`backend/apps/core/models.py:10`),
одна на сервис, с кэшем 5 секунд.

| Граница | Механизм | Что видит клиент |
|---|---|---|
| HTTP-запрос снаружи | `ServiceGateMiddleware` по префиксу URL | 503 с конвертом |
| Вызов соседа в процессе | `require_service()` → `ServiceDisabled`, ловится в `api_view` | тот же 503 |
| Celery-задача | `require_service()` первой строкой задачи | задача падает |
| `/django-admin/` | `ServiceGatedAdminMixin` | `PermissionDenied` по-джанговски, без JSON |

Тело 503 собирается единственной функцией `disabled_payload`
(`backend/apps/core/services.py:19`), чтобы межаппная деградация выглядела для
клиента так же, как внешний отказ:

```json
{"detail": "...", "code": "service_disabled", "service": "hr"}
```

Переключение: `manage.py service <имя> --on|--off [--message "..."]`.

Кэш **fail-open**: недоступный Redis не роняет трафик — ошибка логируется, и
запрос идёт прямо в БД (`backend/apps/core/services.py:39-52`). Ошибка самой БД
не глушится.

## 6. Три пространства имён, и они не совпадают

Самая частая ловушка проекта. У домена есть **три** разных имени, и для
четырёх аппок они расходятся:

| Django `app_label` | Имя сервиса в реестре | URL-префикс |
|---|---|---|
| `users` | `users` | `/api/users/v1/` |
| `hr` | `hr` | `/api/hr/v1/` |
| `tasks` | `tasks` | `/api/tasks/v1/` |
| `cms` | `cms` | `/api/cms/v1/` |
| `messenger` | `messenger` | `/api/messenger/v1/` |
| `contracts` | `contracts` | `/api/contracts/v1/` |
| `signoff` | `signoff` | `/api/signoff/v1/` |
| **`approvals`** | `approvals` | **`/api/requests/v1/`** |
| **`mail`** | `mail` | **`/api/email/v1/`** |
| **`media_files`** | **`media`** | **`/api/media/v1/`** |
| — (нет аппки) | `conference` | `/ws/sfu/` |

Расхождения — наследство FastAPI-поколения, где сервисы назывались иначе.
Живут в двух картах, стоящих рядом в одном файле намеренно:
`PREFIX_TO_SERVICE` и `APP_LABEL_TO_SERVICE`
(`backend/htqweb/middleware/service_gate.py:6` и `:38`). Правятся только вместе.

Полный список имён реестра — `KNOWN_SERVICES`
(`backend/apps/core/models.py:5`). Обратите внимание на `conference`: сервис
есть, Django-аппки за ним нет — он гейтит сигналинг SFU.

## 7. Схемы Pydantic

`backend/apps/<домен>/schemas.py` — валидация запросов и формы ответов.
Перенесены из FastAPI-сервисов почти без изменений. В `api_view` схема
подключается параметром `body=`, ответы возвращаются экземплярами схем и
сериализуются декоратором.

## Чек-лист правки

- Логика — в `services/`, не во вью.
- Ошибка — `{"detail": ...}`, свой формат не изобретаем.
- Сосед — только через `interface.py`.
- Новый путь — зарегистрировать обе формы, со слэшем и без.
- Новая Celery-задача — `require_service()` первой строкой.
- Меняете имя сервиса — правьте обе карты в `backend/htqweb/middleware/service_gate.py`.
