# Grafana Alerting — Phase 7.3.c

**Date:** 2026-04-28
**Provisioned via:** [infra/logging/grafana-provisioning/alerting/](../infra/logging/grafana-provisioning/alerting/)

## What's covered (Loki-backed)

The current observability stack is Loki only — no Prometheus + node/redis/postgres
exporters. Alerts that can be expressed as log-pattern matches are wired now;
system-level metrics (Postgres disk %, Redis memory %) are deferred until those
exporters are added.

| Rule UID | Severity | Trigger |
|----------|----------|---------|
| `htqweb-error-rate-5m`        | warning  | `count_over_time({level="ERROR"}[5m]) > 10` per service |
| `htqweb-gateway-5xx-1m`       | critical | nginx 5xx ratio > 5% in 1m (matches ` 5\d\d ` in access log) |
| `htqweb-db-connection-errors` | critical | >3 Postgres-related connection errors in 5m (refused / auth / FATAL) |
| `htqweb-frontend-errors`      | warning  | >20 `frontend_client_error` log lines in 5m (SPA telemetry forward) |

All rules deliver to the `htqweb-default` contact point (no-op email until SMTP env
is configured — alerts are still visible inside the Grafana UI under
**Alerting → Alert rules**).

Verify after `docker compose restart grafana`:
```bash
curl -s -u admin:admin http://localhost:3001/api/v1/provisioning/alert-rules \
  | jq '.[] | {uid, title, severity: .labels.severity}'
```

## Deferred (need Prometheus + exporters)

These were in the Phase 7.3.c plan but require infrastructure that isn't in the
current compose stack:

- **Postgres disk usage > 80%** — needs `postgres_exporter` + Prometheus.
- **Redis memory > 80%**       — needs `redis_exporter` + Prometheus.
- **Container CPU/RAM**        — needs `cAdvisor` or `node_exporter`.

Adding these is a separate Phase (call it 7.3.e if it matters): introduce a
Prometheus container in compose, scrape Loki + the exporters, then add a
second alert group `htqweb-prom` mirroring the Loki one for metric thresholds.

## Quick test

To exercise `htqweb-error-rate-5m` end-to-end:
```bash
for i in $(seq 1 12); do
  docker compose exec -T cms-service python -c \
    "import structlog; structlog.get_logger().error('synthetic test alert', n=$i)"
done
# Wait ~1 minute, then:
curl -s -u admin:admin http://localhost:3001/api/v1/provisioning/alert-rules/htqweb-error-rate-5m
# State should flip Pending→Alerting in the UI.
```
