# БЗО, B6.2 — импорт книги CashFlow в модуль (план исполнителя B)

**Цель.** `bpp_import_cashflow` грузит рабочую книгу финансистов (`CashFlow.xlsx`: листы «Бюджет», «Реестр договоров», «Операции») в модуль БЗО. Старые `import_cashflow` / `import_cashflow_operations` пишут в `contracts`, который замораживается. Импорт повторяется (Q-D05).

**Приёмка (мастер-план):** тот же файл даёт те же суммы, что старый импорт.

## Решения

| # | Решение | Источник |
|---|---|---|
| D-B62-1 | **Только добавляет.** Новые договоры и операции заводятся, загруженные не трогаются. Расхождения с книгой (другой лимит, другая сумма договора) — в отчёт; правит ФД корректировкой бюджета и допсоглашением | Руслан 30.09 |
| D-B62-2 | **Бюджет из книги — черновик для ФД.** Проекту без бюджета импорт заводит черновик с листа «Бюджет», ФД утверждает его в модуле. Пока бюджет не утверждён, договоры и операции проекта не грузятся: в отчёте строка «утвердите бюджет и запустите снова». Остальные проекты грузятся. Повтор после утверждения безопасен (D-B62-1) | Руслан 30.09 |
| D-B62-3 | **Разбор книги — дословно из `contracts`:** колонки по заголовку, БИН с потерянным нулём, аванс долей или процентом, даты Excel, отпечаток строки операции. Копия в `services/cashflow/workbook.py`: `contracts` замораживается и когда-нибудь уйдёт, а разбор нужен дальше. Тест сверяет новую копию со старым разбором на одной книге | мастер-план («те же суммы») |
| D-B62-4 | **Одна книга — одни данные, с какого бы пути они ни пришли.** Договоры узнаются по идентификатору LARK, операции — по отпечатку строки (`ops:…`), через `MigrationLink` (`cashflow.agreement`, `cashflow.operation`). Перенос B6.1 записывает эти ключи и для перенесённых документов, и для закрытых, ушедших в сальдо. Поэтому книга, загруженная после переноса «Договоров», ничего не удвоит | Руслан 30.09 (повтор без дублей) |
| D-B62-5 | **Карты — по названиям книги:** «администратор → Проект» и «администратор × код программы → статья». Черновики строит `--draft-maps`, проверка — как в B6.1: статья только существующая (D-B61-3), неполная карта — стоп | как D-B61-3/4 |
| D-B62-6 | **Документы — как в B6.1:** договор реестра → «Действует» (подписан в LARK) со скрытой технической заявкой. Позиции у договора одна — «Предмет договора», в книге позиций нет. Открытый договор резервирует свои оплаты из книги. Операция «по договору» → счёт по договору, «без договора» → счёт без договора со своей технической заявкой. Обе — «Оплачено» с отметкой оплаты на дату счёта | старый импорт: «книга — учёт уже случившихся расходов» |

## Задачи

1. `services/cashflow/workbook.py` — разбор книги (D-B62-3) + тест равенства со старым разбором.
2. B6.1 пишет ключи LARK и отпечатков (D-B62-4): `migration_snapshot` отдаёт `external_id` договоров, счетов и оплат; открытые связываются со своим документом, закрытые — с сальдо статьи.
3. Карты (`services/cashflow/maps.py`) и проверка.
4. Загрузка (`services/cashflow/load.py`):
   - контрагенты;
   - бюджеты — черновик или сравнение с существующим;
   - договоры и операции только утверждённых бюджетов.

   Общие куски с B6.1 (техническая заявка, счёт, разбивка по позициям) выносятся в общий класс.
5. Команда `bpp_import_cashflow <файл> --company … [--draft-maps | --projects-map --articles-map --actor] [--dry-run] [--report]`, отчёт xlsx.
6. Приёмка:
   - та же книга через старый импорт в `contracts` и через новый в модуль — одни суммы: лимиты, договоры, операции;
   - книга после переноса B6.1 не добавляет ничего;
   - повтор ничего не добавляет.
7. Документация: `CLAUDE.md`, `STRUCTURE.md`, ранбук — раздел «CashFlow», сверка B.
