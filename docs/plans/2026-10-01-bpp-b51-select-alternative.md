# БЗО, B5.1 — выбор альтернативы (план исполнителя B)

**Цель.** Выбранное альтернативное предложение (АП) заменяет исходный документ:
- исходный счёт или договор получает финальный статус «Заменён альтернативой», его этапы согласования аннулируются, позиции освобождаются;
- создаётся черновик нового документа на альтернативного контрагента, запись KPI «Предварительный».

**Кто выбирает:**
- по счёту без договора — ФД кнопкой «Выбрать»;
- по договору — голосованием ФД и ГД на их этапах согласования; решающий голос — ГД (D-25).

Задача мастер-плана — B5.1. Приёмка — AC-015, AC-016, AC-017 (ТЗ §12.4, §26), с поправкой D-26: у нового договора предсогласован только этап ГД.

**Стартовая точка:** `new-module-BPP-ruslan` с влитой веткой A этапа 5 (`411c9c0`, PR #43 — до его сведения в общую ветку).

**Спека:**
- ТЗ §12.4–12.5, BR-093, BR-094, BR-096, операции SelectAlternativeOffer и DecideApprovalStep (§26);
- мастер-план: B5.1, D-25, D-26, §2.6;
- контракт A — `services/alternatives/lifecycle.py` (`mark_selected`, `options_for`, `check_option`) и `kpi.py` (`create_preliminary`, `sync_for_document`);
- остаток B в плане этапа 5 A — B-1…B-7.

## Решения

| # | Решение | Источник |
|---|---|---|
| D-B51-1 | **По счёту выбирает ФД — держатель задачи решения по этому счёту**, как у «Оплатить» (`decisions._task_of`), плюс узел `bpp.alternatives.select` `edit`. Комментарий обязателен, не короче 10 символов (тот же `comment_of`, что у отказа) | ТЗ §12.4 п.3, BR-060 |
| D-B51-2 | **Порядок блокировок выбора по счёту: процесс signoff → строка счёта** — тот же, что у общего инбокса. Иначе выбор и решение из инбокса взаимно блокируются (B-7). Для этого в signoff — `interface.lock_process_for(subject_type, subject_id)` | план этапа 5 A, B-7 |
| D-B51-3 | **Вид нового документа:** договор, если исходный — договор или сумма АП в KZT больше 1000 МРП на сегодня; иначе счёт без договора. Из АП берутся контрагент, валюта, НДС, позиции и цены. Номер документа контрагента — пустой, вносит автор вместе с файлом. Связь «АП → новый документ» — `AlternativeOffer.result_type/result_id`, отдельных столбцов у счёта и договора нет. На форме — «Основание: альтернатива АП-…» | BR-094, ТЗ §12.4 п.4 |
| D-B51-4 | **Автор нового документа — автор заявки позиций.** Позиции из разных заявок — автор первой по системному номеру позиции. Черновик ему и ждёт: он прикладывает файл и отправляет | D-25, В-23 |
| D-B51-5 | **Частичная АП — два черновика:** по альтернативе (позиции АП, её контрагент и цены) и по остатку (прочие позиции исходного, его контрагент и цены, вид исходного). KPI — только по черновику альтернативы | D-25, Q-E09 |
| D-B51-6 | **BR-093:** АП дороже исходного на Δ (в KZT) — Δ не больше свободного остатка статьи на момент выбора, иначе 422 текстом ТЗ | BR-093 |
| D-B51-7 | **КП переезжает в новый документ** файлом типа `alternative_offer` («КП альтернативы»). Тип добавляется владельцам счёта и договора, необязательный, до 5 документов | ТЗ §12.4 п.4, контракт A |
| D-B51-8 | **Договор — варианты голоса signoff.** `bpp.agreement` регистрирует `options`/`check_option` из `lifecycle` и `on_option` — голос в «Историю изменений» договора (доменная запись, D-26). `on_approved` сначала смотрит `signoff.final_option`: вариант-АП — выбор (процесс уже согласован, отзывать нечего), исходный — прежний путь «Действует». Ветвление стоит до смены статуса | D-26, B-6 |
| D-B51-9 | **Новый договор по АП, выбранной голосованием, — этап ГД предсогласован** при отправке: `start_process(preapproved=[{position_id, actor_id, label}])`. Должность и человек — из решающего голоса процесса исходного договора. ФД проверяет новый договор своим этапом, ТД и ОД согласуют обычным порядком. Новый договор по АП к счёту (BR-094) предсогласований не получает — выбирал только ФД | D-26 |
| D-B51-10 | **B-3:** при отправке нового документа сумма в KZT отличается от АП не больше чем на 5 %, иначе 422 «нужен повторный выбор». Экономию по новой сумме пересчитывает `kpi.sync_for_document` | ТЗ §12.4 п.5 |
| D-B51-11 | **Уведомления (центр уведомлений):** автору нового документа — черновик ждёт; автору исходного — документ заменён. Уже проголосовавшим по договору о новой АП (§12.4 п.1) — из подачи АП, строкой в `offers.submit` (зона A) | ТЗ §12.4 п.1, §12.7 |

## Задачи

1. **signoff:** `lock_process_for` — блокировка идущего процесса объекта (D-B51-2), тест.
2. **Сборка нового документа** — `services/selection/documents.py`:
   - черновики из АП (счёт или договор, остаток при частичной АП);
   - перенос КП, связь АП → документ, `kpi.create_preliminary`, уведомления;
   - из `agreements.create_from_plan` выносится сборщик `_new_agreement`, как `_new_invoice` у счёта.
3. **Выбор по счёту** — `services/selection/invoice.py::select` и ручка `POST invoices/<id>/select-alternative` `{offer_id, comment, expected_version}`. Тесты — AC-015, AC-016, BR-093, BR-096, 403 не своей задаче, частичная АП.
4. **Голосование по договору:**
   - `approval_hooks`: `options`/`check_option`/`on_option`;
   - ветвление `on_approved`;
   - предсогласование ГД при отправке нового договора;
   - уведомление проголосовавшим.
   
   Тесты — голоса ФД и ГД, решает ГД, расхождение голосов.
5. **B-3** — 5 % при отправке нового счёта и договора.
6. **Типы файлов КП** у владельцев счёта и договора (D-B51-7).
7. **Фронт:**
   - кнопка «Выбрать» в слоте `renderSelect` блока «Альтернативы» формы счёта (ФД), диалог с комментарием, переход к новому документу;
   - «Основание: альтернатива АП-…» на форме нового документа;
   - vitest.
8. **B-5:** сверка крючков — каждый новый переход в «Заменён альтернативой» зовёт `kpi.sync_for_document`.
9. **Сквозные сценарии** — в `apps/bpp/tests/selection/`:
   - AC-015 от выбора до KPI;
   - AC-016;
   - голосование до «Действует» нового договора и подтверждения KPI.

   Документация — CLAUDE.md, API.md, STRUCTURE.md, сверка B §23.
