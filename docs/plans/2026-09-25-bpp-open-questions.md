## A. Организационные

<a id="q-a01"></a>**Q-A01. Граница модуля по коду.** Модуль БЗО — это только `contracts` + `signoff` + шаблон закупа в `approvals`, или в него входят и доработки `tasks.Project`, `apps.access`, `hr` (должности ФД/ТД/…), `htqweb` (идемпотентность, версии), уведомления?
- **Зачем:** определяет, что попадает в план и в оценку.
- **По умолчанию:** входит всё из §6.2 анализа; платформенные доработки делаются общими, а не «под БЗО».
- **Блокер:** нет.
- **Ответ 25.09 ✅** Модуль = contracts + signoff + approvals + зависимости из других аппок, в том числе будущий модуль «Закупки», который разрабатывается вне этого ТЗ.
- **Проверка:** Границу с будущим модулем «Закупки» фиксируем в спеке (что туда уйдёт — тендеры и сравнение КП, исключённые §1.2 ТЗ). Имя новой аппки выбрать так, чтобы оно не заняло слово «закупки» — [Q-E22](#q-e22).

<a id="q-a02"></a>**Q-A02. Распределение работ A/B и владение.** Принимаем распределение из §6.2 анализа? Кто утверждает изменения общего движка signoff — они затрагивают согласование заявок, договоров и десяти кадровых предметов `hr.*`?
- **Зачем:** без владельца signoff два исполнителя будут менять движок с разных сторон.
- **По умолчанию:** B — владелец signoff; A делает ревью изменений движка; распределение — как в §6.2, с пересмотром после оценки задач.
- **Блокер:** да, для плана.
- **Ответ 25.09 ✅** Как по умолчанию: владелец signoff — B (Руслан); изменения движка B отправляет A на подтверждение.

<a id="q-a04"></a>**Q-A04. Судьба текущего процесса «Заявка на закуп».** Сейчас это шаблон конструктора форм (`seed_purchase_request_template`): строка бюджета, позиции без цены, маршрут «Подбор поставщика (сравнительная таблица) → Счёт на оплату (PDF, сумма = выбранному предложению) → финансовый директор», договор или счёт заводятся по одобренной заявке. ТЗ описывает другой процесс: заявка с ориентировочными ценами → ТД → ОД → План закупок → договор или счёт. Что делаем:
- (а) заменяем шаблон типизированной заявкой ТЗ и снимаем шаблон с публикации;
- (б) оставляем оба — шаблон для «прочих» закупок;
- (в) адаптируем шаблон под ТЗ, не заводя модель.

Что с уже поданными по шаблону заявками и договорами/счетами, которые ссылаются на них через `request_id`?
- **Зачем:** определяет модель заявки, План закупок и миграцию.
- **По умолчанию:** (а); существующие заявки дорабатываются в старом процессе до закрытия, новые создаются только по ТЗ.
- **Блокер:** да.
- **Ответ 25.09 ⚠️** Вариант (в): адаптировать шаблон под ТЗ, не заводя модель. Поданные по шаблону заявки тестовые — их можно удалить, справочные данные сохранить. В топ-10: «интегрировать в модуль, который прописан в ТЗ».
- **Проверка:** **Противоречит [Q-C05](#q-c05)**: там принята типизированная модель заявки. Шаблон конструктора не даёт внешних ключей позиций, резерва бюджета под блокировкой строки (BR-011), статусов позиций и Плана закупок (CALC-005). Предлагаемое прочтение — [Q-E01](#q-e01).
- **Ответ 26.09 ✅** Принято прочтение Q-E01: типизированная заявка; шаблон закупа снимается, его механика переходит в модуль.

<a id="q-a05"></a>**Q-A05. Живые данные.** В каких схемах компаний уже есть данные contracts (импорт CashFlow, ручной ввод) и сколько их? Нужна ли их полная миграция в новую модель (бюджет на проект, единый счёт, закрывающие документы) или БЗО стартует с чистого листа с даты X, а старое остаётся архивом?
- **Зачем:** от ответа зависит объём работ на 30–50% (миграции expand/contract по каждой схеме).
- **По умолчанию:** мигрируем справочники (контрагенты, программы → статьи) и действующие договоры; закрытые документы остаются как есть, только на чтение.
- **Блокер:** да.
- **Ответ 25.09 ⏳** Мигрировать (топ-10). Какие справочники мигрировать — уточнить у Алгазы.

- **Как в ТЗ.** У проекта ровно один бюджет на весь срок. Лимиты ставятся по статьям. Лимит меняют корректировкой, она создаёт новую версию (v2, v3…), старая сохраняется. Остаток статьи считается за весь срок проекта.
- **Как сейчас в коде.** Бюджет заводят на проект в конкретной стране, на конкретный год и в конкретной валюте. На следующий год — новый бюджет. Остаток считается внутри года, неизрасходованное на следующий год не переходит.
- **Разница для финансов.** «На весь срок» — один лимит: перерасход одного года покрывается экономией другого. «По годам» — у каждого года свой лимит, контроль жёстче, но переходящие остатки переносятся вручную.
- **Что нужно от Алгазы:**
  1. весь срок или по годам;
  2. если весь срок, нужен ли дополнительно контроль остатка по периодам (год, квартал — В-04);
  3. что такое «открытый бюджет на основную компанию» из ответа Q-D02 ([Q-E13](#q-e13)).

**Итог 26.09:** 1 — весь срок (ответ Q-B01, тело); 2 — контроля по периодам нет (умолчание); 3 — служебный проект «Общие расходы компании» (умолчание Q-E13). Мастер-план D-06.

<a id="r4"></a>**R4. Дробление счетов** (к В-14, BR-047).

<a id="r6"></a>**R6. Что такое «Счёт на оплату» и номер `СЧ-`** (к [Q-B09](#q-b09), топ-10 №6).

- **Не файл, а карточка документа в системе.** В ТЗ «Счёт на оплату» — карточка со всем, что нужно для оплаты и контроля:
  - поставщик и сумма;
  - основание — по договору или без договора;
  - строки по позициям заявки;
  - решение ФД;
  - отметки оплаты бухгалтера;
  - статус сверки с банком.
  
  Файл счёта от поставщика (pdf, jpg) прикладывается к карточке.
- **`СЧ-ГГГГ-NNNNNN`** — внутренний номер карточки, например `СЧ-2026-000123`. Система выдаёт его автоматически при первом сохранении. Нумерация сквозная в пределах года, номер никогда не повторяется.
- **Зачем номер.** Бухгалтер вписывает его в назначение платежа в банк-клиенте. При загрузке выписки система находит номер в назначении и сама сопоставляет платёж со счётом (§11). Так видно, что оплата действительно прошла и на какую сумму. Без единого номера автосверку сделать нельзя.
- **АВР, накладная, счёт-фактура** — файлы (pdf, xlsx, docx, xml), прикладываемые к карточке счёта. По ТЗ — до оплаты, по вашему ответу на В-11 — после ([Q-E07](#q-e07)).
- **Вопрос к Алгазы (Q-B09):** вести ли все платежи — без договора, по договору, предоплаты и транши — единым реестром карточек «Счёт на оплату» с номером `СЧ-`.

**Итог 26.09:** ответ Q-B09 «По умолчанию» — единый реестр карточек «Счёт на оплату» со сквозным `СЧ-`; АВР, накладная, счёт-фактура — файлы на карточке, после оплаты. Мастер-план D-11, D-13.
