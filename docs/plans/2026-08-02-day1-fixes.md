## Баг 2. Страница «фризится» после закрытия окна

> **Диагноз исправлен по результатам проверки.** Первая версия этой спеки называла причиной
> размонтирование открытого диалога (`{open && <Dialog open={open}/>}`). Гипотеза **не
> подтвердилась**: тест показал, что React корректно отрабатывает cleanup при размонтировании и
> блокировку снимает. Ниже — причина, воспроизведённая в коде.

### Причина (воспроизведена)

Уточнение от заказчика: ломается **почти каждая модалка**, закрытая «Отменой» или «крестиком»;
симптом — «всё видно, но клики не работают». Это залипший `pointer-events: none` на `<body>`.

Условие срабатывания: **внутри модалки открыт вложенный Radix-слой** (`Select`, `Popover`,
`DropdownMenu`, `Command`), и модалку закрывают, **не выбрав в нём значение**. Тогда диалог уходит
из DOM, а блокировка на `<body>` остаётся.

Матрица проверки (jsdom, реальные события):

| Сценарий | `<body>` после закрытия |
|---|---|
| Простая модалка → «Отмена» | чисто |
| Простая модалка → «крестик» | чисто |
| Модалка + Select, **значение выбрано** → «Отмена» | чисто |
| Модалка + Select, **значение НЕ выбрано** → «Отмена» | **`pointer-events: none` остался** |
| Модалка + Select, **значение НЕ выбрано** → Escape | **`pointer-events: none` остался** |
| Размонтирование открытой модалки | чисто (гипотеза не подтвердилась) |

Почему «почти каждая»: выпадающий список есть практически в любой форме проекта — в диалоге
сотрудника это `Select` статуса и `Popover`+`Command` для пользователя/должности/отдела.

**Усугубляющий фактор:** `@radix-ui/react-alert-dialog@1.1.14` тянет собственную копию
`@radix-ui/react-dialog@1.1.14` рядом с верхнеуровневой `1.1.15`. Реестр слоёв у Radix модульного
уровня — две копии не видят слои друг друга.

### Решение (сделано)

Инвариант вместо заплатки на конкретную модалку: **если в DOM нет ни одного открытого модального
слоя, блокировки на `<body>` быть не должно.**

- [`lib/bodyPointerEvents.ts`](../../frontend/src/lib/bodyPointerEvents.ts) — `releaseStuckBodyLock()`: снимает блокировку, только если не осталось `[role=dialog|alertdialog|listbox|menu]` и `[data-radix-popper-content-wrapper]`. Пока хоть один слой открыт — не вмешивается.
- [`components/BodyPointerEventsGuard.tsx`](../../frontend/src/components/BodyPointerEventsGuard.tsx) — `MutationObserver` на атрибуты `<body>` и порталы, работу откладывает на `requestAnimationFrame` (на момент мутации закрывающийся слой ещё в DOM). Смонтирован один раз в `App.tsx`.
- [Тесты](../../frontend/src/components/__tests__/BodyPointerEventsGuard.test.tsx): первый **воспроизводит утечку** без сторожа (упадёт, если баг Radix починят и сторож станет не нужен), второй проверяет снятие через реальную подписку `MutationObserver`, третий — что при открытой модалке сторож не вмешивается.

Одно место чинит все модалки сразу, включая те, что появятся позже. Осталось на будущее:
дедупликация версий `react-dialog` через `overrides` и то, что один Escape закрывает и Select, и
модалку разом (отдельный UX-дефект, на фриз не влияет).
