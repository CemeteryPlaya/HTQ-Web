# Автоматизация Trello на доске «Задачи HTQ» — разбор

26.10.2026 · Руслан · источник — Trello, доска «Задачи HTQ» (`trello.com/b/OQ9ectwQ`), раздел «Автоматизация» (Butler) · только просмотр: конструктор открывался и отменялся, ничего не сохранено и не изменено.

Зачем: этапы S4 (движок) и S5 (интерфейс) [Trello-плана](2026-10-22-kanban-trello-automation-plan.md) переносят автоматизацию Trello в модуль «Задачи». Здесь — дословно, что настроено на доске, полный каталог конструктора и как всё это ложится на нашу модель. Решения и отступления от плана — в §8.

## 1. Экран «Автоматизация»

- Открывается значком ⚡ в шапке доски — полноэкранная панель поверх доски, слева разделы:
  - **Автоматизации:** Правила, Запланировано, Дата выполнения;
  - **Пользовательские кнопки:** Кнопки на карточке, Кнопки на доске;
  - **Автоматизации приложения:** Просмотреть приложения (интеграции);
  - **Больше:** Рекомендации, Активность; внизу — Отчёты, Отправить отзыв, Помощь.
- **Список** — по карточке на автоматизацию: фраза моноширинным шрифтом, переключатель «Включить на этой доске», значки «Добавить в библиотеку», «Редактировать», «Копировать», «Удалить», «Журналы», «Управлять досками», справа часы — подсказка «Дата последнего изменения».
- **Над списком:** «Создать автоматизацию»; «Фильтр» (поиск, по библиотеке, только включённые, только выключенные); «Библиотеки» (ярлыки-группы автоматизаций, у доски их нет); «Администратор» (смотреть автоматизации других участников — в Trello они личные).
- **Пустой раздел** — пояснение, три примера и видео.
- **У кнопок** вместо «Управлять досками» — «Изменение видимости»: доска (только эта / все доски пространства) × люди (только я / все участники пространства) и переключатель «Скрыть для меня на этой доске».
- **В окне карточки** кнопки — во всплывающем «Автоматизация» нижней панели окна: «Взять в работу», «На доработку», «Сдать», «+ Добавить кнопку», значок правки. Нажатие сразу выполняет действия.

## 3. Конструктор

### 3.1. Как устроен

- Правило — три шага: «Select trigger → Select action → Review and save», кнопки Save и Cancel.
- Триггер — одна строка-шаблон с полями и выпадающими списками, «+» добавляет её в правило.
- Действий — сколько угодно; на шаге проверки каждое показано фразой с корзиной, есть «+ Add another action».
- Переключатель «Advanced» показывает расширенные варианты (воронка-фильтр, «кем сделано»).
- Команда по расписанию и по сроку собирается так же: «расписание или срок → действия».
- Кнопка: значок (около 66 на выбор), название, «Enabled by default», у кнопки карточки ещё «Close card when action is performed», затем действия.

### 3.2. Триггеры правил

- **Card Move:**
  - карточка «added to / created in / emailed into / moved into / moved out of» доску или колонку X («added» — создана, скопирована, перенесена или пришла письмом);
  - карточка «archived / unarchived»;
  - колонка создана;
  - в колонке X «exactly / more than / fewer than» N карточек.
- **Card Changes:**
  - карточка отмечена «complete / incomplete»;
  - метка X (или любая) «added to / removed from»;
  - вложение (с фильтром по типу) «added to / removed from»;
  - «I am / @user / someone» «added to / removed from» карточку;
  - голос.
- **Dates:**
  - срок или начало «set on / moved in / removed from»: «moved» — только если дата уже была, «set» — всегда;
  - уточнение окна: «in this week…» или «less than N days from now»;
  - разбор даты из названия на естественном языке (англ.).
- **Checklists:**
  - чек-лист X «added to / removed from»;
  - «checklist X / a checklist / all checklists» «completed / made incomplete»;
  - пункт «X / any» «checked / unchecked», можно уточнить «in a checklist named Y»;
  - срок у пункта (платно);
  - пункт добавлен в чек-лист X — с переменной `{checklistitemname}` для действий.
- **Card Content:**
  - «the name / the description» «starts with / ends with / contains / not …» текст, `{*}` — любые символы;
  - комментарий добавлен, с фильтром «starting with текст»;
  - упоминание «someone / I / @user» «in a checklist / in a comment / in the description».
- **Fields:**
  - все поля заполнены;
  - поля X, Y заполнены;
  - поле X «set / cleared»;
  - поле X «set to» значение;
  - флажок X «checked / unchecked»;
  - число X «greater than / less than / …» N;
  - дата X в окне.

### 3.3. Условия — «фильтр карточки» (воронка у триггера)

- **Basic:**
  - «in / not in» колонке X;
  - «with / without» меткой X;
  - роль карточки — board/link/mirror/separator, у нас не нужна;
  - «assigned to / assigned only to / not assigned to» × «me / anyone / member».
- **Dates:**
  - «with / without» «a / an overdue» сроком;
  - «with / without» датой начала;
  - срок «today / tomorrow / this week / next week / this month / next month»;
  - срок «in less than / in more than / in / in between» N дней.
- **Checklist:** «with all checklists complete / with an incomplete checklist / with checklist X / without checklist X / without checklists».
- **Content:**
  - «with» «a name / a description / a name or a description», сравнение «starting with / ending with / containing / not …» с текстом;
  - «with» пустым описанием.
- **Fields:**
  - все поля заполнены;
  - поля X, Y заполнены;
  - поле X задано;
  - поле X равно значению;
  - флажок X отмечен;
  - число X «greater than …» N;
  - дата X «in this week…» или «less than N days from now».
- Каждое условие переключается «with / without» (или «in / not in»); условий у триггера может быть несколько.

### 3.4. Кем сделано (значок человека у триггера)

«by anyone (default) / by me / by @user / by anyone except me / by anyone except @user».

### 3.5. Действия правил и кнопок карточки

- **Move:**
  - «move / copy» карточку «в верх / в низ» колонки X (можно другой доски);
  - «в верх / в низ» своей колонки;
  - «archive / unarchive».
- **Add/Remove:**
  - создать карточку «new / unique» с названием, описанием, колонкой, метками, чек-листом, участниками, датой («unique» — только если такой ещё нет, иначе правило останавливается);
  - зеркало;
  - «add / remove» метку X;
  - стикер;
  - «add / remove» ссылку-вложение;
  - «remove» «the due date / the start date / the cover image / all the labels / all the stickers / all the checklists / all the members»;
  - сменить цвет колонки.
- **Dates:**
  - «mark the card as» «complete / incomplete»;
  - «set» «due / start» дату:
    - «now»;
    - «in N minutes / hours / days / working days / weeks / months» (с временем);
    - «the next monday…»;
    - «on the 1st of this month»;
    - «on the first monday of the month»;
    - «on january 1st [год]»;
    - «on the date in custom field X»;
  - «move the» «due / start» дату: «to the same day next week», «by N days / working days / weeks / months», «to the next monday» — сдвиг сохраняет время;
  - «move the due date by the same amount of time» (для каскада).
- **Checklists:**
  - «add / remove» чек-лист X — копия чек-листа с этим именем с другой карточки доски, можно указать карточку-источник;
  - пустой чек-лист «X»;
  - «add / remove» пункт в чек-лист X;
  - назначить пункт (платно);
  - сроки пунктов (платно);
  - «check / uncheck» пункт X (в чек-листе Y);
  - «check / uncheck» все пункты «in checklist X / in all checklists»;
  - «reset all the checklists»;
  - «remove all the (checked/…) items from checklist X».
- **Members:**
  - «join / leave» карточку;
  - «subscribe to / unsubscribe from»;
  - «add / remove» @участника;
  - добавить участника «at random / in turn» из участников указанной карточки (по умолчанию — доски);
  - «remove all the members».
- **Content:**
  - переименовать (`{cardname}` — прежнее название);
  - задать описание;
  - написать комментарий (`@card` уведомляет всех на карточке, `@board` — всех на доске, кроме себя);
  - письмо на адреса (через `;`) с темой и текстом;
  - HTTP-запрос «get / post / put / delete» url.
- **Fields:**
  - очистить поле;
  - задать значение;
  - «check / uncheck» флажок;
  - «increase / decrease» число на N;
  - дата поля — как у «set date»;
  - сдвинуть дату поля.
- **Sort** (колонка карточки или указанная):
  - по сроку, началу, названию, голосам, возрасту, времени в колонке, полю или меткам в заданном порядке;
  - «ascending / descending», есть второй ключ.
- **Cascade** — найти связанную карточку и применить к ней (зеркала, зависимости).
- **Интеграции** — Jira, Bitbucket, Slack.

### 3.6. Команды по расписанию и кнопки на доске

- **Расписание:**
  - «every day / weekday»;
  - «every <выбранные дни>»;
  - «every N weeks on <дни>» с датой начала;
  - «every first monday of the month»;
  - «every month on the 1st»;
  - «every year on the 1st of january»;
  - у каждого варианта — время.
- **Действия уровня доски** (у расписания и у кнопки на доске):
  - **Add Card:** создать карточку («new / unique»); найти карточку и скопировать в колонку.
  - **Move Cards:**
    - «move / copy» все карточки колонки X в Y;
    - «move / copy» каждую карточку, подходящую под фильтр;
    - карточки старше N дней — из X в Y;
    - N случайных из X в Y;
    - архивировать выполненные, старые или с меткой.
  - **Lists:** создать, архивировать или сортировать колонки — у нас колонок-объектов нет.
  - **Sort:** как в §3.5.
  - **Other:**
    - отчёт по карточкам доски с фильтром — подставляется в другое действие;
    - письмо;
    - HTTP-запрос.

### 3.7. Команды по сроку

- Варианты триггера:
  - «the moment / on the day» срок наступил;
  - за или через N «days / working days / hours» до или после срока (с временем);
  - «on the monday before» срока.
- У триггера фильтр карточки, как в §3.3.
- **Не задним числом:** «за 2 дня до срока» не сработает у карточек, которым до срока уже меньше 2 дней, — только когда это наступит с ходом времени.

### 3.8. Переменные

`{cardname}`, `{checklistitemname}`, `{*}` (любой текст в шаблоне сравнения), `@card`, `@board`; переменные упоминания из триггера.

## 4. Журнал, активность, рекомендации

- **«Журналы» правила:**
  - «Текущее количество запусков в месяц»;
  - переключатель «только предупреждения и ошибки»;
  - записи со временем:
    - «Requesting card to check trigger condition(s).» — триггер пришёл, условия проверены;
    - «Running automation on board X.» → строки действий («Moved card <ссылка> to list «Готово».», «Set Custom Field «Взята в работу» to …», «Checked 4 items in checklist «Чек-лист»…») → «The automation finished running.» → «Итого операций: N»;
    - «The automation has been created / modified from: … to: …», «enabled on N boards»;
  - «Загрузить ещё».
- **«Активность»** — те же записи по всем автоматизациям и лимиты пространства: запуски за период (без ограничений), операции за период (лимит 150 000).
- **«Рекомендации»:**
  - Trello предлагает кнопки на карточке или доске из повторяющихся ручных действий: «move the card to list «Исполнение» — выполнялось 39 раз, последний раз 2 дня назад»;
  - у каждой рекомендации — кнопки «Добавить» и «Скрыть».

## 5. Что видно из журнала про исполнение

- **Правила запускают друг друга.**
  - Правило 4 добавляет пустой чек-лист — правило 7 добавляет в него четыре пункта.
  - «Сдать» отмечает выполненной — правило 3 отмечает пункты и переносит в «Готово». Отметки пунктов запускают правило 5 несколько раз, правило 8 снимает «Просрочено».
  - Цепочка не ограничена одним шагом: этим и держится процесс HTQ.
- **Повторы.** Одно правило в цепочке срабатывает несколько раз, например на каждый отмеченный пункт. Если делать уже нечего, остаётся пустой запуск («The automation finished running» без действий).
- **Срок проверяется около 00:00.** Метка «Просрочено» ставится записью «26 октября в 00:00».

## 6. Как это ложится на наш проект

- **Колонка — статус (K-02).**
  - «Добавлена в колонку X» = задача получила статус X.
  - «Перенесена из X в Y» = смена статуса.
  - «Колонка создана», колонки другой доски и «сменить цвет колонки» не нужны: цвет задаёт администратор в настройках доски.
- **«Отмечена выполненной» = перенос в «Готово»** (статус `done`), «снять отметку» = уход из него. Отдельного признака у нас нет, поэтому:
  - правила 3, 5, 8 выражаются через перенос;
  - правило 6 не нужно — уход из «Готово» и есть снятие отметки;
  - кнопка «Сдать» = «перенести в «Готово»».
- **Архив** = статус «Отменена» (`cancelled`), «вернуть из архива» — обратный переход.
- **Участники.** Участники Trello = исполнители. «Join» = добавить сделавшего, «subscribe» = наблюдать. Руководитель задачи — своё поле, есть отдельные триггер и действие.
- **Метки** общие на компанию (K-22), цвет и название — из справочника.
- **Свои поля** — этап S3 (`BoardField`/`TaskFieldValue`), типы текст, число, дата, флажок, список. «Приоритет» остаётся встроенным.
- **Даты.** Даты задач без времени, поэтому минуты и часы не нужны. «Рабочие дни» считаются по производственному календарю `refdata` (как сроки задач).
- **Упоминаний `@` в комментариях нет.** `@card` в комментарии автоматизации = уведомить участников задачи через `task_notify`.
- **Письма на произвольные адреса и HTTP-запросы не переносим:** это канал утечки данных компании наружу. Вместо письма — действие «уведомить сотрудников», через центр уведомлений (колокольчик, почта и Telegram по их настройкам).
- **Не переносим** (решение 22.10): зеркала, каскад, голоса, стикеры, обложки, Jira, Bitbucket, Slack.
- **Автоматизации принадлежат доске, а не человеку.**
  - Правит их администратор доски (K-39), автор виден у правила.
  - «Только для меня», «Администратор» и «Управлять досками» не нужны.
  - Кнопку на карточке видят все, кто вправе вести задачу.
- **Срок по времени.** Команды по сроку идут периодической задачей. «Через N дней после срока» срабатывает один раз на тройку «правило + задача + срок»: перенесли срок — сработает снова.

## 7. Процесс HTQ на нашем каталоге (шаблон K-40)

Колонки — как в Trello-плане: «Постановка задачи» `backlog`, «Ожидающие исполнения» `todo`, «Исполнение» `in_progress`, «В ожидании» `blocked`, «Готово» `done`; «Протокольные поручения» — метка. Поля — «Причина ожидания» (текст), «Взята в работу» (дата).

| Trello | У нас |
|---|---|
| 1 | исполнитель добавлен · в колонке «Постановка задачи», есть срок → в «Ожидающие исполнения», вниз |
| 2 | срок поставлен · в «Постановка задачи», назначена на кого-нибудь → в «Ожидающие исполнения», вниз |
| 3 | перенесена из «Исполнение» в «Готово» → отметить все пункты всех чек-листов |
| 4 + 7 | создана на доске · без чек-листа «Чек-лист» → чек-лист «Чек-лист»; чек-лист «Чек-лист» добавлен → пункты «Ознакомиться с задачей», «Выполнить задачу», «Проверить результат», «Отправить отчёт руководителю» |
| 5 | пункт отмечен · в «Исполнение», все чек-листы выполнены → в «Готово», вверх |
| 6 | не нужно |
| 8 | перенесена в «Готово» → снять метку «Просрочено» |
| 9 | поле «Причина ожидания» задано · в «Исполнение» → в «В ожидании», вверх |
| 10 | поле «Причина ожидания» очищено · в «В ожидании» → в «Исполнение», вверх |
| 11 | пункт «Выполнить задачу» отмечен · в «Ожидающие исполнения» → поле «Взята в работу» = сейчас; в «Исполнение», вверх |
| 12 | **запрет переноса** «Постановка задачи» → «Исполнение», текст правила 12 |
| 13 | **запрет** «Исполнение» → «Ожидающие исполнения», если «Взята в работу» задано, текст правила 13 |
| 14 | **запрет** «Ожидающие исполнения» → «Готово», если есть невыполненный чек-лист, текст правила 14 |
| 15 | **запрет** «Готово» → «Ожидающие исполнения», если все чек-листы выполнены, текст правила 15 |
| 16 | **запрет** «Исполнение» → «Готово», если есть невыполненный чек-лист, текст правила 16 |
| 17 | **запрет** «Ожидающие исполнения» → «Исполнение», если «Взята в работу» не задано, текст правила 17 |
| 18 | перенесена из «Готово» в «Исполнение» · все чек-листы выполнены → сбросить чек-листы; комментарий «@card Задачу вернули на доработку…» |
| 19 | комментарий начинается с «На доработку» · в «Готово» → в «Исполнение», вверх |
| срок | через 1 день после срока · срок просрочен → метка «Просрочено» (тёмно-красная); комментарий «@card Срок выполнения прошёл…» |
| «Взять в работу» | поле «Взята в работу» = сейчас; в «Исполнение», вниз; добавить нажавшего исполнителем |
| «На доработку» | в «Исполнение», вверх |
| «Сдать» | в «Готово» |

**Запреты — только для ручных переносов.**
- В Trello правила 12–17 возвращают карточку уже после переноса. У нас перенос просто не происходит: 409 `automation_blocked` с текстом правила (K-38).
- Переносы самой автоматизации запреты не проверяют. Иначе «Взять в работу» и «Сдать» упирались бы в собственные запреты, как в Trello их обходят только условия правил.

Шаблон работает в таком виде, только если правила запускают друг друга (см. §8, вопрос 1). Например: «Сдать» → правило 3 отмечает пункты → правило 8 снимает «Просрочено». Без цепочек эти действия пришлось бы дописывать прямо в кнопки и правила, и самостоятельные правила, собранные «как в Trello», вели бы себя иначе.

## 8. Отступления от Trello-плана и вопросы

**Ответы пользователя 26.10:** цепочки — как в Trello, с ограничителями из п. 1; дополнения каталога из п. 2 — в S4; «Рекомендации» переносим (в отличие от п. 3) — в интерфейсе S5; остальное из п. 3 не переносим; журнал — по п. 4. Этапы по очереди: S3 (поля) → S4 (движок и шаблон HTQ) → S5 (интерфейс), после каждого — тесты, живая проверка на стенде с дампом и коммит без пуша.

1. **Цепочки правил (K-37).** План: изменения от автоматизации новых правил не запускают («глубина 1»). Trello запускает, и процесс HTQ на этом держится (§5). Предложение — цепочки с ограничителями:
   - глубина до 5;
   - одно правило срабатывает на задаче один раз за цепочку;
   - не больше 50 действий на запрос;
   - упёрлись в предел — правило не выполняется, запуск пишется в журнал с предупреждением.
2. **Чего нет в каталоге плана, но есть в Trello:**
   - условия «назначена только на», «срок в окне» (сегодня, неделя, месяц), «чек-лист X есть или нет», «описание или название содержит», «кем сделано: кроме меня или кроме @человека»;
   - триггеры «вложение добавлено или удалено», «пункт добавлен», «метка снята», «руководитель или исполнитель снят»;
   - действия «скопировать задачу», «отписаться», «добавить исполнителя по очереди», «удалить пункты чек-листа», «снять дату начала», «дата из поля»;
   - массовые действия расписания и кнопок доски: перенести все или каждую подходящую, старше N дней, N случайных, отменить выполненные или старые.
   
   Всё это вписывается в движок без новых сущностей — предлагается включить в S4.
3. **Не переносим:** письма на произвольные адреса и HTTP-запросы (замена — «уведомить сотрудников»), рекомендации, библиотеки, личные автоматизации, «Администратор», разбор даты из названия.
4. **Журнал запусков** — по образцу Trello:
   - у правила и сводно по доске;
   - фильтр «только предупреждения и ошибки»;
   - запись: «проверено, условия не сошлись» или «выполнено: <действия>», итог операций;
   - создание и правка правила («было → стало»);
   - хранение — 90 дней.
