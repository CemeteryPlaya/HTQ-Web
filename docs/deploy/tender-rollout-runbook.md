# Выкатка тендерного модуля закупок в пилот — ранбук (T5.7)

Модуль `apps.tender` выкатывается **в пилот на одну компанию — холдинг `hi-tech-group`** (мастер-план тендерного модуля, T-01; спека этапа 5, §3 T5.7). Остальные компании получают таблицы модуля (миграции идут по всем схемам), но модуль у них **выключен рубильником компании** `CompanyModule`. Выкатка идёт после модуля БЗО (зависимость — пакеты `bpp.interface` B-1/B-2, миграции `bpp/0021`–`0022`) и тем же порядком «код → `migrate_shared` → `migrate_companies` → команды по компании → рубильники».

Решения и ссылки: мастер-план — [docs/plans/2026-10-06-tender-master-plan.md](../plans/2026-10-06-tender-master-plan.md) (T-01…T-31), спека этапа 5 — [docs/plans/2026-10-20-tender-stage5-spec.md](../plans/2026-10-20-tender-stage5-spec.md) (S5-01…S5-20), антивирус — [antivirus-runbook.md](antivirus-runbook.md), поддомены — [subdomains-runbook.md](subdomains-runbook.md).

## 1. Предусловия

- **Бэкап БД снят**, откат — из него (раздел 3). Репетиция на свежем дампе боя пройдена (протокол — раздел 5, заполняет пользователь).
- **Модуль БЗО выкачен и работает у холдинга**: роли `bpp-*`, маршруты `bpp_configure_routes`, утверждённые бюджеты проектов — тендерная заявка уходит в БЗО заявками на закуп (ЗЗ, `source="tender"`) и без них не отправится.
- **Курсы валют НБРК в `refdata`** заведены на даты вскрытий: сравнение берёт курс последнего дня не позже даты вскрытия (T-12); нет курса — суммы в KZT пусты, утвердить выбор нельзя (`E-TND-10`).
- **Штат холдинга сверен**: должности «Технический директор» (проверка качества по умолчанию, T-11), «Финансовый директор», «Менеджер по закупкам», «Руководитель проекта» — `tender_assign_roles` и `tender_configure_route` ищут их **по точному названию**.
- **Антивирус включён** (`ANTIVIRUS_CLAMD_HOST=clamav`, `--profile antivirus`, [antivirus-runbook.md](antivirus-runbook.md)): портал принимает файлы от внешних поставщиков, без сканера — только по отдельному решению. Пока freshclam качает базы, загрузки отвечают 503 — так задумано.
- **nginx**: `location ^~ /api/tender/v1/supplier/` (лимит `tender_portal`, маскировка токена в логе, `client_max_body_size 21M`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`) — в `infra/nginx/default.conf`. Перед окном — `nginx -t` на боевых сертификатах (хвост T3.1).
- **Cookie устройства** на бою — `__Secure-tender_device` (https). `TENDER_PORTAL_INSECURE_COOKIE` в боевом окружении **не задаётся** (только стенд по http).
- **Почта поставщикам (этап 4) ещё не выкачена**: писем-приглашений, OTP-перепривязки и автозакрытия приёма по сроку нет. Ссылку поставщику закупщик копирует из диалога «Ссылки для участников» (она показывается один раз) и пересылает сам; потерянную — «Перевыпустить ссылку». Ящик `tender@` и SPF/DKIM/DMARC — задача T4.4, к этому окну не относится.

## 2. Шаги

Платформенные шаги (1–6) идут один раз; шаги 7–9 — только у холдинга.

### Шаг 1. Остановить воркеры

```bash
docker compose stop backend-worker backend-beat
```

### Шаг 2. Обновить код: бэкенд, фронт, шлюз

```bash
docker compose up -d --build backend-web backend-asgi frontend
docker compose --profile production exec nginx nginx -t
docker compose --profile production exec nginx nginx -s reload
```

Пересборка фронта нужна: без неё на бою нет страниц `/tender` и `/supplier/:token`. Перезагрузка nginx нужна: без неё нет локации портала `^~ /api/tender/v1/supplier/` — лимита, маскировки токена в логе и заголовков. С `RUN_MIGRATIONS=1` `backend-web` сам выполнит шаг 3; иначе — руками.

### Шаг 3. `migrate_shared`

```bash
docker compose exec backend-web python manage.py migrate_shared
```

Общие миграции модуля: `access/0026_grant_tender_module`, `access/0027_tender_roles` (узлы `tender.*`, роли `tender-*`), `files/0006_tender_file_types`, `files/0007_tender_offer_type`, `files/0008_tender_receipt_types` (типы файлов ТЗ, КП, сканов приёмки и фото). Периодических задач у модуля нет.

### Шаг 4. `migrate_companies` — все компании

```bash
docker compose exec backend-web python manage.py migrate_companies
```

Тенантные миграции: `bpp/0021_request_source`, `bpp/0022_tender_documents` (поля счёта и договора из тендера, приёмка), `tender/0001_core` … `tender/0008_delivery`. Миграции — только expand: колонки и таблицы добавляются, ничего не удаляется, поэтому компании без модуля их не замечают. Сводки холдинга пересобираются в конце команды. Вывод команды — строка на компанию с версиями аппок: у каждой должно быть `tender=0008_delivery` и `bpp=0022_tender_documents`.

### Шаг 5. `tenancy_status`

```bash
docker compose exec backend-web python manage.py tenancy_status
```

Раскладка таблиц по схемам: таблицы `tender_*` — в схеме каждой компании, в `public` их нет (версии миграций печатает шаг 4).

### Шаг 6. Рубильники: модуль только у холдинга

Рубильник сервиса без строки — «включено», у компании без строки `CompanyModule` — тоже «включено»: от шага 2 до этого шага модуль открыт всем компаниям (ролей `tender-*` ни у кого ещё нет, поэтому войти в него некому). Поэтому сразу после миграций закрыть модуль всем, кроме холдинга, и только потом выдавать роли:

```bash
# у каждой действующей компании, кроме hi-tech-group (суперпользователь):
#   PATCH /api/companies/v1/companies/<slug>/modules/tender  {"enabled": false, "message": "Тендерный модуль — пилот холдинга"}
# (или django-admin → «Company modules»: строка tender, enabled = нет)
docker compose exec backend-web python manage.py service tender --on
docker compose start backend-worker backend-beat
```

Проверка: у холдинга `/tender` открывается, у дочерней — пункта меню нет, `/api/tender/v1/…` отвечает 503 `service_disabled` с именем `tender`; портал поставщика дочерней компании — тоже 503.

### Шаг 7. Роли модуля: `tender_assign_roles --company hi-tech-group`

```bash
docker compose exec backend-web python manage.py tender_assign_roles --company hi-tech-group --dry-run
docker compose exec backend-web python manage.py tender_assign_roles --company hi-tech-group
```

Выдаёт роли `tender-*` должностям (закупщики — «Менеджер по закупкам» и «Руководитель проекта» → `tender-buyer`, ТД → `tender-quality`, ФД → `tender-fd`, бухгалтерия и ОД → `tender-viewer`). Идемпотентна: повтор печатает «уже есть». Строки «нет должности» — разрыв штата, до шага 9 его закрыть.

### Шаг 8. Маршрут утверждения выбора: `tender_configure_route --company hi-tech-group`

```bash
docker compose exec backend-web python manage.py tender_configure_route --company hi-tech-group --dry-run
docker compose exec backend-web python manage.py tender_configure_route --company hi-tech-group
```

Маршрут `tender.award` — «Проверка качества → ФД» (T-11, S5-08): первый этап называет сам тендер (назначенный проверяющий, иначе держатели должности «Технический директор»), второй — ФД; флаги «самому себе нельзя» и «комментарий отказа от 10 символов». Без маршрута «На утверждение» отвечает 409 `E-SGN-01`. Активный маршрут команда не трогает.

### Шаг 9. Дымовая проверка у холдинга (короткий ручной вид)

Под закупщиком холдинга:

1. Заявка тендера на одну позицию → «Отправить в БЗО» → ЗЗ утверждены ТД и ОД (маршрут БЗО).
2. Тендер: срок, схема оплаты, один потенциальный поставщик с БИН → «Опубликовать» → ссылка показана один раз.
3. Ссылка в другом браузере: «Открыть предложение», цена, «Отправить предложение» (согласие на ПДн).
4. Карточка: «Вскрыть» (все ответили — можно до срока) → «Сравнение» видно, «Экспорт в xlsx» скачивается.
5. «Выбор» → поставщик в строке → «Сохранить выбор» → «На утверждение»; ТД и ФД утверждают в «Ждёт меня».
6. «Передать в БЗО» → вкладка «Поставка»: черновик счёта (или договора свыше 1000 МРП на документ) — ссылкой; в БЗО его ведут как обычно.
7. Тестовые документы и тендер отменить (тендер — «Отменить тендер», черновики БЗО — удалить).

Тот же сценарий автоматически — `frontend/tests/e2e/41_tender_award.spec.ts` (на стенде, не на бою).

## 3. Откат

- **Модуль выключить, данные не трогать**: `manage.py service tender --off` (на всей платформе) — ручки и портал отвечают 503, ссылки поставщиков перестают работать, в БЗО остаются созданные документы и ЗЗ (их ведут как обычно; замок T-07 снимается только сервисами модуля, поэтому ЗЗ из тендера в БЗО остаются запертыми — это ожидаемо).
- Миграции не откатываются: они только добавляют, а таблицы без модуля никто не читает.
- Полный откат окна — из бэкапа (раздел 1), если сломан не модуль, а миграции БЗО `0021`–`0022`.
