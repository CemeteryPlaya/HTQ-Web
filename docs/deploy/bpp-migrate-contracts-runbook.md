# Перенос «Договоров» в модуль БЗО — ранбук (B6.1)

Команда `bpp_migrate_contracts` переносит данные раздела «Договоры» (`apps.contracts`) в модуль «Бюджет, закупки и оплаты». План и решения — [docs/plans/2026-09-30-bpp-b61-migrate-contracts.md](../plans/2026-09-30-bpp-b61-migrate-contracts.md).

**Что переносится:**
- все контрагенты;
- администраторы бюджета — как «Проекты»;
- бюджеты — годы суммируются по статье, только KZT;
- открытые документы:
  - договоры;
  - счета без договора;
  - оплаты, предоплаты, АВР и накладные открытых договоров;
  - подотчёт с авансовыми отчётами.

**Что не переносится:** закрытые документы. Они остаются в «Договорах» только на чтение, а их расход держит в модуле сальдо статьи.

**Как команда себя ведёт:**
- Компания переносится **одной транзакцией**: отказ на любом шаге откатывает всё.
- `--dry-run` откатывает и удачный прогон — остаётся отчёт.
- Повторный запуск ничего не дублирует.

## Сначала — репетиция на копии боевой базы

1. **Дамп прода в копию.**

   ```bash
   pg_dump -Fc -h <прод> -U htqweb htqweb > prod-$(date +%F).dump
   createdb -h <копия> -U htqweb htqweb_rehearsal
   pg_restore -h <копия> -U htqweb -d htqweb_rehearsal prod-$(date +%F).dump
   ```

   Дальше все команды выполняются со стеком, у которого `DB_HOST`/`DB_NAME` смотрят на копию.
2. **Схемы до текущей версии:**
   - `manage.py migrate_shared`;
   - `manage.py migrate_companies` — нужны `bpp` до `0014_migration_link` и `files/0004`.
3. **Роли и маршруты модуля** (зона A, A6.3): `bpp_assign_roles --company <slug>`, `bpp_configure_routes --company <slug>`. Сама команда переноса маршрутов и ролей не требует: документы переезжают без запуска согласования.
4. **Черновики карт:**

   ```bash
   manage.py bpp_migrate_contracts --company <slug> --draft-maps maps/
   ```

   Команда создаёт в `maps/` три файла:
   - `projects.csv` — строка на администратора бюджета. Поле `project_code` предложено: код уже заведённого «Проекта» с тем же названием, иначе `П-<id>`. Код «Проекта» после переноса не меняется — ФД проверяет каждый.
   - `articles.csv` — строка на программу. Поле `article_code` предложено, только если код программы совпал с кодом статьи справочника и не конфликтует с другой программой.
   - `conflicts.txt` — коды программ, которые у финансистов повторяются в разных проектах. Такие программы сопоставляются только вручную.
5. **ФД заполняет карты.** Файлы открываются в Excel: разделитель «;», кодировка UTF-8 с BOM.
   - Статьи, которых нет в справочнике, УК сначала заводит в «Справочниках» → «Статьи» с нужной группой: «Снабжение» или «Проектное управление». Команда сама статьи не заводит (D-B61-3).
   - Статью выбирают **по названию программы, а не по коду**. У финансистов один код в разных источниках значит разное: на репетиции 3020 — «Земляные работы» в «Договорах» и «Сопровождение проекта» в книге CashFlow.
   - Несколько программ можно свести в одну статью — лимиты сложатся.
6. **Проверочный прогон с отчётом:**

   ```bash
   manage.py bpp_migrate_contracts --company <slug> \
       --projects-map maps/projects.csv --articles-map maps/articles.csv \
       --actor <user_id АДМ> --dry-run --report rehearsal.xlsx
   ```

   Неполная карта останавливает команду до первой записи — с перечнем, что поправить.
7. **Разбор отчёта `rehearsal.xlsx`** (листы):
   - **«Сверка»** — по каждой паре «проект × статья»: старые лимит, «занято» и остаток против новых. Колонка `diff` у всех строк = 0. Иначе команда остановилась бы сама.
   - **«Ожидаемые расхождения»** — где остаток в модуле намеренно другой:
     - черновик держит резерв своей технической заявки;
     - подотчёт «На согласовании» стал черновиком;
     - открытый договор без оплат держит 0,01.
   - **«Не перенесено»** — бюджеты и документы в другой валюте, договоры-поступления, файлы платёжных поручений, позиции с неизвестной единицей измерения. Каждую строку просматривает ФД.
   - **«Бюджеты»** — у проекта, чей бюджет в «Договорах» не утверждён, бюджет в модуле — черновик. Документы проекта переносятся всё равно; их резерв появится в карточке бюджета после утверждения.
   - **«Переотправить»** — документы, которые были «На согласовании». Они переехали черновиками, старые согласования отозваны. Их авторы отправляют документы заново по маршрутам модуля.
8. Если отчёт устраивает ФД — репетиция закончена. Копию базы можно удалить.

## Перенос на бою

Одним окном выкатки (A6.3). Порядок:
1. Дамп прода.
2. `migrate_shared` и `migrate_companies`.
3. Роли и маршруты.
4. Прогон с теми же картами без `--dry-run`, с `--report migration-<дата>.xlsx`.
5. Проверки (ниже).
6. Заморозка «Договоров» (A6.2).

**Проверки после переноса:**
- В реестрах договоров, счетов и подотчёта перенесённые документы есть, с пометкой «перенесён».
- Технических заявок переноса нет ни в реестре заявок, ни в Плане закупок.
- Остаток статьи в карточке бюджета совпадает со строкой листа «Сверка».
- Авторам из листа «Переотправить» разосланы напоминания.

**Откат:** восстановить дамп, снятый в шаге 1.

## Маршруты согласования `contracts.*` (Q-D03)

Маршруты старого раздела не переносятся: у документов модуля другие типы и свои флаги. Перед выкаткой:
- выписать из редактора маршрутов (или django-admin → «Маршруты согласования») этапы маршрутов `contracts.agreement`, `contracts.invoice`, `contracts.contract_payment` и остальных `contracts.*` — какие должности на каких этапах;
- сверить с маршрутами, которые завела `bpp_configure_routes`: заявка «ТД → ОД», договор «ФД → ТД → ОД → ГД», допсоглашение — ФД при росте суммы, счёт, подотчёт и авансовый отчёт — ФД;
- расхождения, которые нужно сохранить, внести в редакторе маршрутов модуля до переноса.

## Книга CashFlow (B6.2)

`bpp_import_cashflow` грузит рабочую книгу финансистов прямо в модуль (листы «Бюджет», «Реестр договоров», «Операции»).

**Как себя ведёт:**
- **Только добавляет.** Договор узнаётся по идентификатору LARK, операция — по отпечатку строки.
- Узнанное не переписывается. Разница с книгой (лимит, сумма договора) — лист отчёта «Расхождения с книгой», её правит ФД корректировкой бюджета или допсоглашением.
- **Перенос «Договоров» записывает те же ключи.** Книгу можно загрузить и после него — ничего не удвоится.

**Порядок:**
1. Черновики карт:

   ```bash
   manage.py bpp_import_cashflow CashFlow.xlsx --company <slug> --draft-maps maps/
   ```

   В `maps/` появятся два файла: `projects.csv` — строка на администратора, `articles.csv` — строка на пару «администратор × код программы». Если «Проект» с тем же названием уже есть (например, заведён переносом «Договоров»), черновик сразу предлагает его код.
2. ФД заполняет карты. Правила — те же, что у переноса: статьи только существующие.
3. Проверочный прогон: с картами, `--actor <user_id>` и `--dry-run --report cashflow.xlsx`.
4. Настоящий прогон.
   - Проектам без бюджета импорт заводит **черновик** с листа «Бюджет». Договоры и операции этих проектов ждут: в итоге команды — «ждут утверждения бюджета: N».
5. ФД утверждает черновики бюджетов в модуле.
6. Тот же запуск ещё раз — он загрузит договоры и операции утверждённых проектов.

**Лист «Расхождения с книгой»** повторяется при каждом запуске, пока ФД не поправит лимит или договор: импорт узнанное не переписывает. Договоры книги в отчёте названы номером с LARK — у финансистов номера повторяются.
